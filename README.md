# DEVOPS_SET_D: Campus Library Book Lookup API

[![CI](https://github.com/Hetansh-Pathak/DEVOPS_SET_D/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Hetansh-Pathak/DEVOPS_SET_D/actions/workflows/ci.yml)

This is my solution to the **DevOps Fresher Assessment, Set D** (70 marks). A small
Python book-lookup API is taken from a plain script all the way to a tested,
containerised, Kubernetes-deployed service. Its configuration is generated by Terraform,
it has a CI pipeline, and there's a rehearsed incident with a rollback.

> The application (`app/`) and its unit tests (`tests/`) came with the starter kit and are **unchanged**.
> Everything else in this repo is my work.

## The API

| Endpoint | Expected |
|---|---|
| `GET /healthz` | 200 `{"status": "alive"}` |
| `GET /readyz` | 200 normally, **503 when `FAIL_MODE=1`** |
| `GET /info` | 200 `{"app": "...", "environment": "..."}` from `APP_NAME` and `APP_ENV` |
| `GET /api/books?code=BK-101` | 200 `{"code": "BK-101", "status": "available"}` |
| `GET /unknown` | 404 |

## Quick start (about 2 minutes, needs only Python 3.10+)

```bash
git clone https://github.com/Hetansh-Pathak/DEVOPS_SET_D.git
cd DEVOPS_SET_D

python3 -m unittest discover -s tests -v            # 7 tests -> OK
bash scripts/analyze_logs.sh logs/access.log        # log report

python3 -m app.server                               # start the API on port 8080
# in another terminal or a browser:
curl -i http://127.0.0.1:8080/healthz
curl -i 'http://127.0.0.1:8080/api/books?code=BK-101'
```
On Windows, use `python` instead of `python3`, and run the `bash` line in Git Bash.

**Don't want to install anything?** Open the
[Actions tab](https://github.com/Hetansh-Pathak/DEVOPS_SET_D/actions/workflows/lab.yml),
choose **Lab evidence (manual) → Run workflow**, and GitHub runs the full Docker and
Kubernetes demo for you in about 4 minutes. To see the output, open the run and expand the steps.

## Full instructions

### Prerequisites
Linux, WSL2 or macOS with: Git, Python 3.10+ (I used 3.12), Docker with the Compose plugin,
Terraform 1.5+, kubectl, and kind (or minikube). No cloud account or registry is needed.

### 1. Log analysis (Task 1)
```bash
wc -l < logs/access.log                                             # total
awk '$2 ~ /^4/' logs/access.log | wc -l                             # 4xx
awk '$2 ~ /^5/' logs/access.log | wc -l                             # 5xx
awk '{print $4}' logs/access.log | sort | uniq -c | sort -rn | head -3
bash scripts/analyze_logs.sh logs/access.log        # exit 0
bash scripts/analyze_logs.sh missing.log; echo $?   # exit 1
```

### 2. Terraform: generate `generated/service.env` (Task 5)
```bash
cd infra
terraform fmt -check -recursive
terraform init
terraform validate
terraform plan  -var-file=dev.tfvars.example
terraform apply -var-file=dev.tfvars.example
cat ../generated/service.env
terraform plan -var=port=80          # rejected: port must be 1024-65535
cd ..
```
Inputs are typed and validated: `port` must be 1024 to 65535, `fail_mode` must be 0 or 1,
and `app_env` and `log_level` must come from fixed lists.

**State and generated files stay out of Git.** `.gitignore` lists `*.tfstate`, `*.tfstate.*`,
`.terraform/`, `*.tfvars` (except `*.tfvars.example`), `generated/service.env` and `.env`.
Check with `git check-ignore -v infra/terraform.tfstate`. Only `.terraform.lock.hcl` is
committed, which is intended because it pins the provider version. A team setup would also
use a remote backend.

### 3. Docker and Compose (Task 2)
Run Terraform first. Compose reads `generated/service.env`.
```bash
docker compose up --build -d
docker compose ps                                   # (healthy)
curl -i http://127.0.0.1:8080/healthz               # 200
curl -i http://127.0.0.1:8080/readyz                # 200
curl -i 'http://127.0.0.1:8080/api/books?code=BK-101'
docker exec campus-library-api id                   # uid=10001(app)
docker compose logs --tail 20
docker compose down --remove-orphans
```
To run all of the above in one go: `bash scripts/lab_docker.sh`.

### 4. CI (Task 3)
[`ci.yml`](.github/workflows/ci.yml) runs on every `push` and `pull_request` with `permissions: contents: read`.
1. **test** job: `python -m compileall` (syntax check), then all unit tests.
2. **docker-build** job (`needs: test`): builds `campus-library:${{ github.sha }}`, then smoke-tests
   the endpoints and checks that the container isn't root. Nothing is pushed anywhere.

To see the gate work, a failing test was pushed to branch `demo/failing-test`, and the Docker build job
was skipped ([run](https://github.com/Hetansh-Pathak/DEVOPS_SET_D/actions/runs/45978589020)).

### 5. Kubernetes with kind (Task 4)
```bash
kind create cluster --name campus-lab
docker build -t campus-library:1.0.0 .
docker tag campus-library:1.0.0 campus-library:1.0.1
kind load docker-image campus-library:1.0.0 campus-library:1.0.1 --name campus-lab

kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/configmap.yaml -f k8s/deployment.yaml -f k8s/service.yaml
kubectl -n devops-assessment rollout status deployment/library-api
kubectl -n devops-assessment get deploy,pods,svc        # 2/2 Ready, ClusterIP 80/TCP

kubectl -n devops-assessment port-forward svc/library-api 18080:80 &
curl -i http://127.0.0.1:18080/readyz
curl -i 'http://127.0.0.1:18080/api/books?code=BK-101'
```
The manifests use a ClusterIP Service on port 80 that targets 8080. Readiness checks `/readyz`
and liveness checks `/healthz`. Each Pod requests 50m CPU and 64Mi memory, with limits of
250m CPU and 128Mi memory. Pods run as non-root with a read-only root filesystem and all
capabilities dropped. The rollout uses `maxUnavailable: 0`, so a bad release never removes a healthy Pod.

### 6. Healthy update, controlled incident and rollback (Tasks 4 and 6)
```bash
# healthy update
kubectl -n devops-assessment set image deployment/library-api library-api=campus-library:1.0.1
kubectl -n devops-assessment rollout status deployment/library-api

# controlled bad release (local lab only)
kubectl -n devops-assessment set env deployment/library-api FAIL_MODE=1
kubectl -n devops-assessment rollout status deployment/library-api --timeout=45s   # times out
kubectl -n devops-assessment get pods                                              # new pod 0/1 Ready
kubectl -n devops-assessment describe pod <new-pod>                                # Readiness probe failed: 503
kubectl -n devops-assessment logs <new-pod>
kubectl -n devops-assessment get events --sort-by=.lastTimestamp

# recover and verify
kubectl -n devops-assessment rollout undo deployment/library-api
kubectl -n devops-assessment rollout status deployment/library-api                 # 2/2 Ready
curl -i http://127.0.0.1:18080/readyz                                              # 200
```
`bash scripts/lab_k8s.sh` runs the whole sequence. The diagnosis, the alert threshold,
the readiness-vs-liveness comparison, the security checks and the runbook are in
**[docs/OPERATIONS.md](docs/OPERATIONS.md)**.

### 7. Cleanup
```bash
kubectl delete namespace devops-assessment
kind delete cluster --name campus-lab
docker compose down --remove-orphans
docker image rm campus-library:local campus-library:1.0.0 campus-library:1.0.1
cd infra && terraform destroy -var-file=dev.tfvars.example     # removes generated/service.env
```
